# Weims Manager 1.1.1

1.1.0 のメンテナンスリリースです。Latest として公開し、Windows GUI と CLI を同梱します。セキュリティ上の問題 1 件と、[Issue #3](https://github.com/H0yeR404/weims-vgpu/issues/3) で報告されたシャットダウンの問題を修正します。

## 変更内容

- **セキュリティ：ゲスト内のソフトウェアが QEMU の制御チャネルに到達できました。** 1.0 から 1.1.0 は、QEMU の制御インターフェイス（QMP）を認証なしでローカル TCP ポートに開いていました。VM 内のソフトウェアは VM 自身のネットワーク経由でこのポートに接続し、ホスト上の QEMU を操作できました。QMP は `%USERPROFILE%\.weims\q` 以下の Unix ドメインソケットに変更され、ゲストのネットワークからは到達できません。詳細は [security-qmp-socket.md](security-qmp-socket.md) を参照してください。
- **Manager の Shut down が機能します**（Issue #3）。このボタンと `Weims.Cli shutdown` は、数ミリ秒しか続かない電源ボタンの押下を送っていましたが、macOS は 0.35 秒より短い押下を無視します。現在は、macOS が「すべてのアプリを終了してシステム終了」に使うキーの組み合わせ（Control-Option-Command-電源キー）を送ります。未保存の書類がある場合は、Apple メニューからの終了と同じく macOS が先に確認します。
- **macOS の電源が切れると QEMU が終了します**（Issue #3）。以前はゲストの終了後も QEMU が黒いウィンドウとして残り、そのウィンドウを閉じるまで VM はロックされ、転送ポートも使用中のままでした。
- Manager とセットアップ画面から QMP ポートの設定を削除しました。既存の VM 設定は保持され、1.1.0 でも開けます。

## インストールと更新

`Weims-Manager-1.1.1-Setup-x64.exe` を実行するか、`Weims-Manager-1.1.1-win-x64.zip` を展開します。どちらも GUI と CLI を含み、別途 .NET は不要です。

1.1.0 と pre.2 は **Software updates → Check for updates → Update now** から更新できます。インストール前に VM とほかの Manager を閉じてください。1.0.1 と pre.1 は手動インストールが必要です。設定ディレクトリ、VM ディスク、ランタイムは変更しません。

修正は 1.1.1 で起動した VM に適用されます。旧バージョンで起動して動作中の VM は、再起動するまで以前の動作のままです。1.1.1 からも管理でき、ゲストの終了後は `Weims.Cli stop` で QEMU を終了できます。

QMP の TCP ポートに接続する独自スクリプトは、ソケットのパスに切り替えてください。VM の `state\runtime.json` にある `qmp_socket` です。

## ランタイムと既知の問題

QEMU/Reims ランタイムは変更せず、[v1.1.0-pre.1](https://github.com/H0yeR404/weims-vgpu/releases/tag/v1.1.0-pre.1) に固定しています。ランタイム ZIP と対応ソースは同リリースにあります。有効な既存ランタイムは Manager 更新で置き換えません。

**解像度変更時などに VM がフリーズする可能性は引き続きあります。調査中です。** 今回の更新では修正していません。[Issue #2](https://github.com/H0yeR404/weims-vgpu/issues/2) では Intel Arc 140T のグラフィックス形式エラーと macOS 初期設定中のフリーズが報告されており、Intel Arc の互換性は十分に検証されていません。クリップボード共有、ファイル共有、システム間のファイルドラッグは含みません。

Manager の Shut down には、ログイン済みでキーボードに応答する macOS が必要です。ログイン画面、macOS インストーラー、復旧環境では検証していません。その場合は画面上のシステム終了ボタンを使用してください。macOS がフリーズした場合の最後の手段は、引き続き Force stop です。重要な VM データはバックアップしてください。

## 検証

自動テスト：Core 86 件、統合 20 件（実際の QEMU プロセスと QMP、ゲストなし）、WPF 46 件、更新選択 22 件、実行環境 4 件。加えて、プロセスとインストール境界を模擬したインストーラー引き継ぎテスト 6 件。

実際のゲスト（macOS 26.7.2、Windows 11 ホスト 1 台）：CLI からソケット経由で起動と状態確認、ゲスト内から以前の QMP ポートに到達できないこと、従来の電源ボタン要求が無視され新しいキーの組み合わせで macOS が終了すること、Manager のウィンドウから起動と終了を行い、その後 QEMU が自動的に終了してポートを解放することを確認しました。

未検証：1.1.0 からの実際の上書き更新、Windows 10、システムコードページ外の文字を含むユーザーフォルダー、ログイン画面やインストーラーでの終了、ほかの macOS バージョン。SHA256 チェックサムを添付します。
